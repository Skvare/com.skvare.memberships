## Testing with cv

The local FOIS install has one Drupal site directory per CiviCRM domain; pass
the site URL so `cv` boots the right domain:

```bash
cd web
../vendor/bin/cv --url=http://dev9.tapuz.israelscouts.org ev 'print_r(CRM_Memberships_Helper::getSettingsConfig());'
```

Useful checks used during the 1.1.0 work (scripts run with `cv scr`):

* Replay `buildAmount` for real parents: set `CRM_Core_Session` `userID`,
  pass a stub with `getLoggedInUserContactID()` to
  `CRM_Memberships_Utils::relatedContactsListing()`, then call
  `getActiveMemberships()`, `getMembershipTobeProcessed()` and
  `prepareMemberList()`; compare JSON before/after a change.
* Anything that writes (contributions, line items, memberships): wrap it in
  `$tx = new CRM_Core_Transaction(); … $tx->rollback()->commit();`.
* Do **not** test receipts through `CRM_Core_BAO_MessageTemplate::sendTemplate()`
  or `renderTemplate()` on FOIS: other extensions' mail hooks (SparkPost)
  write queue rows. Call `memberships_civicrm_alterMailParams()` directly
  with `['workflow' => 'contribution_online_receipt', 'tplParams' => ['contributionID' => …]]`.

## Updating the civix scaffolding

```bash
cd <extension dir>
/path/to/vendor/bin/civix upgrade --no-interaction
```

Review the diff: civix may remove files it considers obsolete (it removed
`sql/auto_install.sql` in the 26.10 conversion).
